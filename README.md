```powershell
# команда для вывода сетей
# открой мне кс
# найди самые большие файлы в этой папке, без удаления
```

Bravel работает внутри привычной оболочки. `cd`, pipes, aliases, completion и обычные команды остаются её задачей. Отдельного shell здесь нет.

## Возможности

| Возможность | Как работает |
| --- | --- |
| `# запрос` | Строка отправляется ИИ, который предлагает команды для вашей ОС |
| `cdm → cmd` | Неизвестная команда вызывает подсказку; простые опечатки исправляются без API |
| Объяснения | Каждый шаг показывает точную команду, назначение и оценку риска |
| Подтверждение | `Y` разрешает план; Enter и `n` отменяют; повышенный риск требует `RUN` |
| Игры Steam | CS2, Deep Rock Galactic и другие установленные игры по полному названию |
| Просмотр | `--dry-run` показывает план без выполнения |
| Gemini и роутеры | Прямой Gemini API, OpenAI, OpenRouter и другие совместимые сервисы |
| Установка и удаление | Python-установщик; `bravel update` и `bravel uninstall` |
| Красивый терминал | Закрытые рамки, цветные панели, `NO_COLOR` и монохромный режим |
| Диалог с агентом | История, анализ вывода, следующие шаги и остановка через Ctrl+C |

## Диалог с агентом

```text
bravel chat
```

Можно запускать из CMD, PowerShell или Bash. На Windows агент по умолчанию выполняет действия в PowerShell без загрузки профиля; менять политику выполнения не нужно. На Linux используется Bash. Явный выбор: `bravel chat --shell cmd`.

Напишите, например: «Проверь сеть и объясни результат» или «Запусти Deep Rock Galactic». Агент показывает точные команды, ждёт подтверждения, выполняет их и анализирует вывод. Каждому следующему плану нужно новое разрешение. Enter и `n` отменяют, повышенный риск требует `RUN`. Ctrl+C останавливает текущую команду или отменяет запрос; диалог остаётся доступным.

| Команда диалога | Действие |
| --- | --- |
| `/help` | Подсказка |
| `/clear`, `clear`, `cls` | Очистить экран без API |
| Обычный вопрос | «Какие программы установлены?» или «Покажи мои игры» |
| `/pwd` | Показать рабочую папку агента |
| `/cd <путь>` | Сменить папку без API, в том числе для CMD |
| `/shell powershell` | Переключить исполнитель на `powershell`, `cmd` или `bash` |
| `/status` | Провайдер, модель, наличие ключа, оболочка и папка |
| `/continue` | Повторно проанализировать последний результат |
| `/history` | Показать текущую историю |
| `/new` | Очистить диалог |
| `/exit`, `exit`, `quit` | Вернуться в обычную консоль |
| `/mode ask` | Подтверждать каждый план (по умолчанию) |
| `/mode preview` | Показывать команды без выполнения |
| `/mode read-only` | Автоматически выполнять только локально разрешённые команды чтения |
| `/save имя`, `/load имя` | Сохранить или загрузить диалог |
| `/sessions`, `/delete имя` | Список и удаление сохранённых диалогов |
| `/context`, `/privacy` | Контекст для API и правила использования данных |

Можно начинать вопросы с `#`. По умолчанию история хранится в памяти сессии, максимум 12 записей; вывод команды ограничен последними 12 КБ. Эти данные используются в последующих запросах к выбранному API. `/new` очищает историю. Максимум восемь циклов на задачу, 120 секунд и 2 МБ записанного вывода на команду. Смена папки PowerShell/Bash сохраняется между действиями; для CMD используйте `/cd`. Переменные оболочки между отдельными командами не сохраняются.

Для одной задачи с анализом результата:

```text
bravel agent "Проверь сеть и объясни результат"
```

`bravel ask` и короткая форма `bravel "запрос"` решают одну задачу с инструментами и анализом; `--dry-run` показывает план без выполнения. Интеграции --emit-command/--command-file возвращают один подтверждённый shell-план. Действия на компьютере выполняются через подтверждённые команды. Управление мышью и распознавание экрана не входят в CLI.

## Агент с инструментами · 0.6.0

В 0.6.6 недопустимая автоматическая проверка результата отправляется модели для одной попытки исправления в рамках общего лимита исправления ответа. Разрешённые проверки теперь сверяются с выбранной оболочкой ещё до публикации плана. Список разрешений не расширяется: модель может исправить/опустить проверку или предложить диагностику отдельной подтверждаемой командой. Переносы и управляющие символы в проверках остаются причиной строгого отказа. Инструкции модели уточняют сериализацию полных путей в PowerShell, группировку процессов и сужение сетевых запросов; это не гарантирует правильность каждого сформированного запроса.

В 0.6.5 смешанный план инструментов и shell-команд отправляется модели для одной попытки исправления до исполнения. Модель выбирает первый отдельный этап и продолжает после его результатов; команды сохраняют обычное подтверждение. Ошибки типа списка инструментов и превышения количества действий тоже можно исправить, с отдельными сообщениями. Невалидный JSON и эти ошибки используют общий лимит одной повторной попытки; повторная ошибка останавливает запрос. Небезопасный формат команды и проверки результата по-прежнему отклоняется строго.

В 0.6.4 исходный вопрос текущей задачи сохраняется отдельно от последних 12 записей истории. API также получает краткий журнал результатов до 40 команд/инструментов (выдержка до 2400 символов на запись, с отметкой неполноты). Новый вопрос и `/new` очищают этот журнал; он не сохраняет разрешения на исполнение. `/context` и `/privacy` отражают расширенный контекст.

После 8 циклов действий агент запрашивает итог по уже собранным данным: подтверждённые факты, предположения и недостающие сведения. Новый план действий в этом режиме не публикуется для исполнения. Повтор подряд того же успешно выполненного плана также переводит исследование к итогу; новый явный запрос начинает отдельную задачу. Неизменённые неудачные действия по-прежнему блокируются. В инструкциях уточнено, что неизвестные приложения нельзя исключать по списку знакомых брендов, а Wintun и владельцы TCP-соединений сами по себе не доказывают владельца VPN-туннеля.

Большой вывод сохраняет первые и последние 6 КБ вместо только последних 12 КБ, явно отмечая пропущенную середину. В чате отображается до 40 строк/около 5 КБ; модель получает более длинную ограниченную выдержку. Заголовки таблиц сохраняются, полные списки при обрезке не считаются проверенными. Невалидный JSON модели может быть исправлен одной дополнительной попыткой до любого исполнения. Эти изменения улучшают управление исследованием, но не гарантируют достоверность всех выводов модели.

В 0.6.3 удалены пользовательские команды `/apps` и `/games`: списки программ и игр запрашиваются обычными словами, соответствующие инструменты доступны агенту. Пустые необязательные фильтры/корни поиска (включая JSON null) считаются отсутствующими; обязательные пути и шаблоны по-прежнему проверяются строго. Неверные параметры инструмента отправляются модели для одной попытки исправления до любого исполнения. Команды вывода Format-Table/List/Wide/Custom/Hex больше не принимаются за форматирование диска; настоящее форматирование, удаление и запись продолжают требовать RUN. Новая строка в редакторе — Ctrl+J или последовательность Esc, Enter; обычный Enter отправляет весь многострочный запрос.

В 0.6.2 ответы форматируются через [Rich](https://rich.readthedocs.io/en/stable/markdown.html): выделение, списки, таблицы и переносы в рамках с учётом ширины Unicode. Итоговый текст озаглавлен «ОТВЕТ»; команды и содержимое файлов показываются буквально, без интерпретации Markdown. Сетевые метаданные не печатаются экранированным JSON. Подсказки опечаток глобальных флагов выводятся одной строкой.

Агенту уточнено: если инструмент не предоставляет нужный показатель или действие, самостоятельно предложить shell-команду, сохранив требования к столбцам, единицам и сортировке. Специальных инструментов для ЦП и памяти не добавлено. Перед показом созданного моделью shell-плана в режиме агента PowerShell разбирает исходник [Parser.ParseInput](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.language.parser.parseinput), Bash — `bash -n`; предложенный код при проверке не исполняется. Ошибка синтаксиса отправляется модели для одной попытки исправления; повторная ошибка останавливает план. Для CMD такой проверки нет. Синтаксическая проверка не доказывает правильность вычислений или безопасность действий; выполнение по-прежнему требует подтверждения, качество сложных команд зависит от модели.

В 0.6.1 `bravel` и `bravel agent` без текста открывают диалог. Опечатка `--versino` предлагает `--version`, не выполняя запрос.

Поиск приложений агентом на Windows дополнен именами, издателями, версиями и папками установки из [реестра установленного ПО](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key). Это сведения об установке, а не гарантированная команда запуска; каталог не включает все portable/Store-приложения. На Linux используются прежние PATH и desktop-записи. Инструменты приложений и процессов поддерживают фильтр по части имени/пути, который выбирает модель.

Процессы сгруппированы по имени и пути исполняемого файла (когда доступен); аргументы запуска не читаются. Поиск файлов также находит папки, сравнивает имена без учёта регистра и сообщает корень и причины неполной проверки. Пустой результат ограниченного поиска не доказывает отсутствие программы. Вместо больших JSON и повторного списка CLI показывает короткий статус, затем ответ модели по полученным данным.

Встроенного веб-поиска пока нет. Инструкция агенту требует явно сообщать это и при необходимости предложить поиск в браузере с подтверждением, вместо утверждений о проверенных сайтах. Неизвестные названия и назначение процессов требуют уточнения или дополнительных наблюдений; качество такого ответа зависит от модели.

Просто задайте вопрос: `bravel "Какие у меня игры установлены?"` или откройте `bravel chat`. Агент выбирает инструменты, получает фактические данные, затем отвечает или предлагает следующее действие. Специальных команд для каждого вопроса запоминать не нужно.

Инструменты агента: установленные игры Steam, запускаемые приложения, ОС и свободное место, процессы, локальные интерфейсы сети, содержимое папок, ограниченный поиск файлов, чтение UTF-8 текста и создание/замена текстового файла. Схемы и параметры проверяет Python; модель не может добавлять произвольные инструменты.

Системные метаданные читаются локально без подтверждения каждого вызова; содержимое текстового файла читается после Y, создание/замена файла требует RUN и показывает полный текст и абсолютный путь. При замене старый файл копируется в новый файл `.bravel-backup-*` рядом с ним. Запись проверяется после выполнения. Поиск ограничен глубиной 5, временем 3 секунды и 200 результатами; скрытые большие каталоги .git, .venv и node_modules пропускаются. Чтение текста ограничено 32 КБ, запись — 8000 символами. Файлы учётных данных исключены; прочитанные данные проходят маскировку перед отправкой к API.

`bravel "запрос"` — короткая форма запроса агенту; `bravel ask --shell cmd "запрос"` задаёт исполнитель. Слово cmd без --shell является частью запроса. Для списка программ или игр задайте обычный вопрос; агент сам получает сведения через инструменты.

Интерактивный stdin у shell-команд отключён. При распознанной ошибке запроса ввода цикл останавливается; соглашения источников автоматически не принимаются. Повтор неизменённой неудачной команды или инструмента блокируется в продолжении задачи. Новый явный запрос начинает новую задачу.

WMIC product / Win32_Product исключены из рекомендуемых способов поиска: [Microsoft описывает возможное восстановление MSI-пакетов при запросе](https://learn.microsoft.com/en-us/powershell/scripting/samples/working-with-software-installations).

## Новое в 0.5.0

- `bravel version` работает так же, как `bravel --version`; `exit`/`quit` и `clear`/`cls` в чате обрабатываются локально.
- Ввод через [prompt-toolkit](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/asking_for_input.html): стрелки ↑/↓, редактирование, Tab для команд, Ctrl+J для новой строки (или последовательно Esc, Enter). Enter отправляет весь запрос. Alt+Enter может перехватываться Windows для полноэкранного режима, поэтому в подсказке Bravel не используется. `--plain` оставляет простой ввод без многострочного редактора. История ввода не записывается на диск.
- По запросу агент ищет программы через PATH, App Paths Windows и стандартные папки установки; на Linux дополнительно читает простые записи `.desktop`. Поиск ограничен этими местами. При неоднозначности агент спрашивает название. Запуск найденного приложения использует реальный путь.
- План может содержать отдельную проверку результата. Она показана до подтверждения и допускает только команды локального списка чтения. Проверка файла или процесса сообщает наблюдение, а не гарантирует, что появился именно новый процесс или открылось окно. На CMD проверка процесса при локальном запуске пока не добавляется; для неё используйте стандартный исполнитель PowerShell.
- `bravel chat --mode preview` и `bravel agent --dry-run "задача"` показывают план. `read-only` разрешает лишь небольшой список вроде `pwd`, `whoami`, `Get-Location`; составные команды, чтение произвольных файлов, запуск программ и изменения продолжают требовать подтверждение. `RUN` определяется локальными правилами и оценкой модели.
- `/save работа` сохраняет очищенный диалог; `/load работа` загружает его, помечая сведения как исторические. Старые планы не получают разрешения на выполнение. `bravel chat --session работа` включает загрузку и автосохранение после задач и при обычном выходе. Файлы находятся рядом с конфигом в `sessions/`; `/delete работа` удаляет один файл. `/new` очищает текущую память, но не удаляет ранее сохранённый файл.
- Контекст, вывод и сохранённая история маскируют известный ключ провайдера и типовые токены, пароли, приватные ключи. Произвольные секреты могут остаться нераспознанными. `/context` показывает контекст до отправки; `/privacy` объясняет состав данных. Ключ авторизации API сохраняется в заголовке запроса к настроенному сервису.
- `bravel doctor` проверяет настройки, PATH, наличие подключения и политику оболочки. `bravel doctor --api` дополнительно делает короткий запрос к модели; он может расходовать токены, команд на ПК не выполняет.
- Обновление показывает итоговую версию и сохраняет один снимок прежнего окружения, установщика и hooks в каталоге `rollback/`. `bravel rollback` восстанавливает его без сети; API-конфиг и диалоги сохраняются. Снимок появляется при обновлении новым установщиком 0.5.0, занимает место примерно как ещё одно окружение и заменяется следующим обновлением. Ошибка pip вызывает попытку автоматического отката. После отката снимок израсходован; снова обновиться можно через `bravel update`.

## Простая установка

Нужен Python 3.10+. Скачайте [`install.py`](https://raw.githubusercontent.com/coylll-dev/Bravel/main/install.py) и выполните:

```powershell
# Windows
python install.py
```

```bash
# Linux
python3 install.py
```

Git, ручной venv и запуск `.ps1` не нужны. Установщик скачивает пакет, создаёт отдельное окружение без прав администратора, подключает Bravel к профилю оболочки и открывает мастер настройки. Выберите провайдера, модель и введите ключ; ввод ключа скрыт. После установки откройте **PowerShell на Windows** или **Bash на Linux**. Windows Terminal — приложение терминала; вкладка CMD внутри него остаётся CMD.

В PowerShell/Bash выполните `bravel doctor`, затем `ai "покажи сетевые подключения"` или наберите `# команда для вывода сетей` и нажмите Enter. `cdm` вызовет предложение исправления; `Y` подтвердит команду.

### CMD и Windows с запрещёнными скриптами

Прямой CLI работает без профиля и без изменения политики PowerShell. В CMD создайте короткую команду на текущую сессию:

```bat
doskey bravel="%LOCALAPPDATA%\Bravel\venv\Scripts\bravel.exe" $*
bravel doctor
bravel ask --shell cmd "команда для вывода сетей"
bravel fix --shell cmd "cdm"
bravel configure
```

Начиная с версии 0.4.1 установщик добавляет CLI в пользовательский PATH Windows. После установки закройте все окна терминала и откройте CMD из меню Пуск: `bravel` будет доступен без `doskey`. Макрос выше нужен только для уже открытой сессии или старой установки. Можно всегда использовать полный путь вместо `bravel`. Автоматические `# запросы` и обработка неизвестных команд требуют PowerShell/Bash с загруженным подключением; в CMD вводите `bravel ask` и `bravel fix`. При `Restricted` профиль PowerShell блокируется; установщик сообщит об этом и оставит политику без изменений.

Можно сразу выбрать Gemini: `python install.py --provider gemini`, или OpenRouter: `--provider openrouter`. Без мастера: `--no-configure`; позже запустите `bravel configure`. На Linux без поддержки venv установите пакет `python3-venv` средствами своего дистрибутива.

| Действие | Команда |
| --- | --- |
| Изменить API, модель или ключ | `bravel configure` |
| Переключиться на Gemini | `bravel configure --provider gemini` |
| Обновить программу | `bravel update` |
| Откатить последнее обновление | `bravel rollback` |
| Проверить API и модель | `bravel doctor --api` |
| Удалить программу и подключение | `bravel uninstall` |
| Удалить также стандартный `.env` с ключом | `bravel uninstall --purge` |

Обновление и удаление завершаются отдельным Python-процессом, чтобы Windows освободила запущенный `bravel.exe`. Дождитесь сообщения о завершении и откройте новый терминал. Удаление сохраняет конфиг API по умолчанию и резервную копию исходного профиля `.bravel.bak`. Пользовательский профиль и чужие окружения не удаляются.

Если команда недоступна, скачанный установщик тоже умеет управление:

```text
python install.py update
python install.py uninstall
```

На Linux используйте `python3`. Каталог установки: `%LOCALAPPDATA%/Bravel` на Windows, `$XDG_DATA_HOME/bravel` или `~/.local/share/bravel` на Linux. Можно выбрать `--prefix`, `--shell`, `--profile`, либо установить только CLI с `--no-profile`. На Windows CLI остаётся доступен через пользовательский PATH; `--no-path` отключает эту настройку. При удалении установщик убирает только добавленную им запись PATH. На Linux подключение PATH идёт через Bash; без профиля используйте полный путь к `venv/bin/bravel`.

Windows подключает найденные PowerShell 7 и Windows PowerShell; Linux — Bash. Zsh/fish и автоматические хуки CMD пока не поддерживаются. Внутренние `.ps1` и `.bash` остаются адаптерами для перехвата `#` и неизвестных команд; пользователю подключать их вручную не нужно. Установщик не меняет политики выполнения PowerShell: если система запрещает профили, используйте CLI по полному пути установки, а для автоматического подключения потребуется разрешённый профиль.

Если у вас была версия 0.3.0 с окном C#, закройте её и выполните новый `install.py update`. Установщик удалит прежнее окно и его ярлыки, сохранив CLI и ключ. Версия 0.4.0 распространяется только как Python CLI.

## Ручная установка для разработки · Windows

Нужны Python 3.10+, Git и PowerShell с PSReadLine. Рекомендуется PowerShell 7.

```powershell
git clone https://github.com/coylll-dev/Bravel.git
cd Bravel
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
bravel init
notepad "$HOME\.config\bravel\.env"
```

Заполните `AI_API_KEY`, `AI_MODEL` и при необходимости `AI_API_BASE_URL`. Затем:

```powershell
bravel doctor
. (bravel integration powershell)
```

Теперь прямо в этой консоли:

```powershell
cdm
# команда для вывода сетей
# открой мне кс
ai 'покажи процессы, которые занимают больше всего памяти'
```

Если активация venv ограничена вашей политикой PowerShell, используйте окружение без активации:

```powershell
$env:PATH = "$PWD\.venv\Scripts;$env:PATH"
.\.venv\Scripts\bravel.exe doctor
. (.\.venv\Scripts\bravel.exe integration powershell)
```

Подключение действует только в текущей сессии. Для автоподключения добавьте в `$PROFILE` путь к установленному скрипту `bravel.ps1`; команда `bravel` должна быть доступна в PATH. `bravel integration powershell` выводит нужный путь. Профиль Bravel сам не меняет.

## Конфигурация

По умолчанию: `~/.config/bravel/.env` на обеих ОС, на Windows — `%USERPROFILE%\.config\bravel\.env`. Это пользовательский конфиг установленной программы. `.env` в корне исходников не требуется и автоматически не читается; `.env.example` — только шаблон для разработки.

```dotenv
AI_PROVIDER=openai
AI_API_BASE_URL=https://api.openai.com/v1
AI_API_KEY=your-api-key
AI_MODEL=gpt-4o-mini
AI_TIMEOUT=45
AI_JSON_MODE=true
AI_MAX_STEPS=5
AI_REQUIRE_KEY=true
AI_COLOR=auto
```

| Параметр | Значение |
| --- | --- |
| `AI_PROVIDER` | `openai`, `gemini`, `openrouter`, `compatible` |
| `AI_API_BASE_URL` | Базовый URL совместимого API, обычно заканчивается `/v1` |
| `AI_API_KEY` | Ключ провайдера; не попадёт в Git |
| `AI_MODEL` | Точное имя модели у вашего провайдера |
| `AI_TIMEOUT` | Время ожидания API, 1–300 секунд |
| `AI_JSON_MODE` | JSON mode; выключите, если провайдер его не поддерживает |
| `AI_MAX_STEPS` | Максимум шагов одного плана, 1–10 |
| `AI_REQUIRE_KEY` | `false` для локального сервиса без ключа |
| `AI_COLOR` | `auto`, `always`, `never` |

Переменные окружения имеют приоритет. Для `.env` прямо в папке проекта задайте путь явно:

```powershell
bravel init --path .env
$env:BRAVEL_ENV = "$PWD\.env"
notepad .env
```

```bash
bravel init --path .env
export BRAVEL_ENV="$PWD/.env"
```

Bravel не загружает конфиги из случайной рабочей папки и не исполняет содержимое `.env`. Для локального сервера можно использовать HTTP только на `localhost`, `127.0.0.1` или `::1`; удалённые endpoints требуют HTTPS.

OpenAI и совместимые роутеры используют [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Прямой Gemini использует [Google generateContent](https://ai.google.dev/api/generate-content), с ключом в заголовке `x-goog-api-key`. [OpenRouter](https://openrouter.ai/docs/quickstart) поддерживает совместимый формат. Ключи не добавляются в URL; перенаправления запросов отключены.

Минимальные конфиги (URL подставляется по провайдеру):

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=your-key
AI_MODEL=gemini-3.8-flash
```

```dotenv
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=your-key
AI_MODEL=openrouter/auto
```

`openrouter/auto` — [автоматический роутер OpenRouter](https://openrouter.ai/docs/guides/routing/routers/auto-router). Можно выбрать точный идентификатор доступной вам модели. Для другого роутера:

```dotenv
AI_PROVIDER=compatible
AI_API_BASE_URL=https://your-router.example/v1
AI_API_KEY=your-key
AI_MODEL=provider/model-id
```

Общий `AI_API_KEY` работает для всех провайдеров и имеет приоритет над `GEMINI_API_KEY`, `OPENROUTER_API_KEY` или `OPENAI_API_KEY`. Шаблон конкретного сервиса: `bravel init --provider gemini`. При смене провайдера обновите URL и модель либо удалите эти строки для значений по умолчанию. Проще использовать `bravel configure`.

## Команды CLI

```text
bravel ask "покажи сетевые подключения"       Предложить и подтвердить команды
bravel ask --dry-run "найди большие файлы"     Только посмотреть план
bravel fix "gti status"                      Исправить неизвестную команду
bravel ask --shell bash "покажи IP"           Явно выбрать оболочку
bravel chat                                 Интерактивный диалог
bravel agent "проверь сеть"                  Одна задача с анализом результатов
bravel doctor                               Проверить настройки без вызова API
bravel init                                 Создать .env, не перезаписывая существующий
bravel configure                            Мастер настройки API и скрытого ввода ключа
bravel update                               Обновить управляемую установку
bravel uninstall                            Удалить управляемую установку
bravel integration powershell               Путь к подключению PowerShell
bravel integration bash                     Путь к подключению Bash
bravel demo                                 Демо интерфейса без API и запуска команд
bravel --version                            Версия
```

`bv` — короткий alias CLI. `ai` — функция, которую добавляет интеграция.

Отключение: `Disable-Bravel` в PowerShell, `bravel_disable` в Bash. Закрытие терминала тоже отключает интеграцию. Чтобы отправить буквальный комментарий `#` в Bash, нажмите Ctrl-J вместо Enter.

## Поведение и ограничения

- Подтверждение разрешает весь показанный план. Шаги запускаются по порядку; при ошибке план останавливается. Отдельных разрешений после каждого шага пока нет.
- Автоматически обрабатываются **неизвестные команды**. Ошибки уже известных команд не перехватываются; их можно описать в `bravel fix` или `# запросе`.
- Интеграция `ai` выполняет команды в текущей оболочке и сохраняет смену папки. Прямой `bravel ask` запускает дочерний процесс; его `cd` не меняет родительскую папку.
- Bash запускает обработчик неизвестной команды в subshell. Для исправлений, которые меняют состояние текущей оболочки, используйте `ai`.
- PowerShell и Bash имеют полные интеграции. В CMD доступен прямой CLI с `--shell cmd`; автоматические `#` и исправления ввода CMD не реализованы.
- Поиск проверяет манифесты и папки игр Steam. Для CS2 и Deep Rock Galactic распознаются короткие названия; для других игр используйте полное название. При нескольких совпадениях агент просит уточнение.
- В `ask` ИИ получает запрос, ОС, shell, текущую папку и небольшой список команд из PATH. В `chat` и `agent` дополнительно используется история диалога и вывода команд. Содержимое файлов и история обычной консоли сами по себе не читаются.
- Оценка риска — подсказка, а не песочница. Подтверждённые команды работают с вашими полномочиями. Ключ храните в `.env`; файл исключён из Git.

Подробности: [архитектура](docs/architecture.md).

## Разработка и обновления

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
```

Тесты API используют локальный HTTP-сервер, настоящий API-ключ не нужен. GitHub Actions проверяет Windows и Linux с Python 3.10, 3.12 и 3.13, включая подключение оболочек и полный цикл установки/удаления в отдельной временной папке.

```bash
git pull --ff-only
python -m pip install -e .
```

После изменения подключения заново откройте терминал или отключите и подключите Bravel.

Для отправки изменений:

```bash
git add bravel tests docs install.py README.md pyproject.toml .env.example .gitignore .github
git commit -m "Describe the change"
git push origin main
```
